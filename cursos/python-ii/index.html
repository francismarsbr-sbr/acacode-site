Sobre el curso

De código suelto a proyectos profesionales

Con base en esta idea, ACACODE trae para ti el curso Aprende a programar con Python «De cero a programador» Módulo II, donde profundizarás en el pensamiento computacional, la toma de decisiones en el programa y la estructuración de proyectos reales con arquitectura profesional.

Tras finalizar esta capacitación, dejarás de escribir código suelto y sabrás estructurar, organizar y maquetar proyectos en Python listos para el mundo real. Aprenderás a utilizar arquitectura profesional, extender el sistema sin romper el código existente, optimizar la velocidad y separar la IA de la lógica de negocio.

Metodología

Arquitectura, patrones y calidad de software

Cuatro bloques progresivos que llevan del diseño orientado a objetos hasta la integración con bases de datos y pruebas automatizadas.

01

POO y Singleton

Entornos virtuales, type hinting y encapsulamiento de recursos de hardware con el patrón Singleton.

02

Herencia y Strategy

Clases base intercambiables, excepciones personalizadas, logging profesional y algoritmos de detección flexibles.

03

Concurrencia y Observer

Multithreading para eliminar lag, decoradores @benchmark y notificaciones automáticas con el patrón Observer.

04

Testing y Factory

PyTest con mocks, persistencia con SQLite/PostgreSQL y fábricas de procesadores para pipelines de visión.

Temario completo

4 objetivos · Módulo II

Fundamentos avanzados y estructuras de datos para construir software robusto, escalable y probado.

01

Objetivo 1

Cimientos y Creación de Objetos

Entornos virtuales y gestión de dependencias profesionales. Tipado estático (type hinting) para definir contratos claros en funciones de imagen (np.ndarray). POO: encapsulamiento de la cámara y el procesamiento.

Patrón Singleton: asegurar que solo exista una instancia de la cámara (recurso de hardware único) en toda la aplicación.

venv Type Hinting POO Singleton
02

Objetivo 2

Herencia y Polimorfismo

Creación de clases base para «Detectores». Manejo de excepciones personalizadas para gestionar fallos en el flujo de video (e.g., FrameCaptureError). Logging en lugar de print() para trazabilidad de errores en el inventario.

Patrón Strategy: permitir que el sistema cambie de algoritmo de detección sin alterar la lógica principal.

Herencia Logging Excepciones Strategy
03

Objetivo 3

Rendimiento y Desacoplamiento

Multithreading (concurrencia): separar la lectura de frames del procesamiento para eliminar el lag. Decoradores: crear un decorador @benchmark para medir el tiempo de inferencia de los modelos de visión.

Patrón Observer: implementar un sistema donde el inventario (base de datos) sea notificado automáticamente cada vez que la cámara detecta un objeto.

Multithreading Decoradores Concurrencia Observer
04

Objetivo 4

Integración y Calidad de Software

Unit testing con PyTest: testear clases de visión usando mocks (imágenes falsas) para asegurar que la lógica de conteo es perfecta. Persistencia de datos: integración limpia con bases de datos (SQLite/PostgreSQL) usando POO.

Patrón Factory: crear una «Fábrica de Procesadores» para instanciar diferentes pipelines de visión según el tipo de producto en el inventario.

PyTest Mocks SQLite Factory
